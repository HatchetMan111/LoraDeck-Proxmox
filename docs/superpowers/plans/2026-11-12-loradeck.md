# LoRaDeck – Implementierungsplan

**Datum:** 2026-11-12
**Spec:** `docs/superpowers/specs/2026-11-12-loradeck-design.md`

## Schritt 1 – Backend-Grundgerüst

- [x] `app/loradeck/__init__.py` mit `__version__ = "1.0.0"`
- [x] `config.py`: `Settings` (DB, Static, Secret, Admin, Session, Cookie,
      Gateway-URL/-Auth, Poll-Intervall, Backup-Dir, Poll-Toggle)
- [x] `auth.py`: scrypt-Hashing, HMAC-Session, LoginGuard
- [x] `db.py`: Schema (`settings`, `state`, `gateway_samples`, `sensors`,
      `events`, `backups`), `connect`, `init_db`, Settings/State-Helfer,
      Sample-/Sensor-/Event-/Backup-Funktionen
- [x] `models.py`: `LoginIn`, `SettingsIn` mit URL-/Intervall-Validierung

**Verifikation:** `python -c "from loradeck import db; ..."` und
`tests/api.sh` nach Schritt 3.

## Schritt 2 – Gateway-Client und Poller

- [x] `gateway.py`: `GatewayClient` auf `httpx`, `GatewayError`,
      `normalize_status`, `normalize_devices`, `build_client`
- [x] `poller.py`: `poll_once` (Status + LNS, Offline-Sample, Sensor-Upsert,
      Events, State) und `Poller`-Hintergrundtask
- [x] `backup.py`: Backup erzeugen (Config ohne Secrets + LNS), Liste,
      Download-Pfad, Löschen, SHA-256

**Verifikation:** `pytest` mit `httpx.MockTransport`:
Erfolg, 401/500/kein JSON, Offline-Übergang, Firmware-Check-Loop.

## Schritt 3 – FastAPI-App

- [x] `main.py`: `create_app(settings, gateway_factory=None)`, Lifespan
      (DB init, Default-Settings, Poller), Security-Middleware, Health,
      Session/Login/Logout, alle Admin-Endpunkte, SPA-Fallback
- [x] `app/tests/`: `conftest.py` (Temp-DB, Static-Dir, Test-Client),
      `fixtures.py` (Awaro-Payloads), `fake_gateway.py` (Dev-/Smoke-Server),
      `test_api.py`, `test_db.py`, `test_gateway.py`, `test_poller.py`

**Verifikation:** `bash tests/api.sh` grün, inkl. 401/429, Settings-Validierung,
Refresh, Backup-CRUD, Firmware-Check.

## Schritt 4 – Frontend

- [x] `web/package.json`, `tsconfig.json`, `vite.config.ts`, `index.html`
- [x] `src/types.ts`, `src/lib/api.ts`, `src/lib/format.ts` (+ `format.test.ts`)
- [x] `components/`: Header, ThemeToggle, LoginForm, StatusPill, Sparkline,
      StatCard, EmptyState
- [x] `pages/`: Dashboard, Sensors, Integrations, Firmware, Backups,
      Settings, NotFound
- [x] `App.tsx`, `main.tsx`, `styles.css`, `public/favicon.svg`

**Verifikation:** `npm ci && npm test && npm run build` ohne TS-Fehler.

## Schritt 5 – Betrieb

- [x] `systemd/loradeck.service`
- [x] `install/loradeck.sh` (Host, Proxmox)
- [x] `install/loradeck-inner.sh` (Container)
- [x] `tests/static-checks.sh`, `tests/api.sh`, `tests/local-smoke.sh`,
      `tests/reboot-test.sh`
- [x] `.github/workflows/ci.yml`
- [x] `.gitignore`, `LICENSE`

**Verifikation:** `bash tests/static-checks.sh`, `shellcheck`, lokaler
Smoke-Test mit Fake-Gateway.

## Schritt 6 – Dokumentation

- [x] `README.md`: Funktionen, Installer-Einzeiler, Optionen, Gateway
      verbinden, Grenzen, HA-Anbindung, Sensor-Kompatibilität
      (Hager TG563A, Netvox RA02A, Deltronic, Nexelec), Sicherheit,
      Troubleshooting, Update/Backup
- [x] `docs/test-evidence.md` mit lokalen Ergebnissen und offenem
      Proxmox-Reboot-Test

**Verifikation:** README-Einzeiler stimmt mit Repo-URL überein;
`static-checks.sh` prüft ihn.

## Abschlussprüfung

```bash
bash tests/static-checks.sh
bash tests/api.sh
(cd web && npm ci && npm test && npm run build)
bash tests/local-smoke.sh
```

Alle Schritte müssen lokal grün sein. Der Proxmox-Reboot-Test bleibt als
dokumentierter, vom Betreiber auszuführender Schritt offen.
